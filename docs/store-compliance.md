# Store compliance review notes

**Status: review notes for the owner and a lawyer, not a compliance claim.** Written 2026-10-18 from the code as it stands. Google's account-deletion page was read for this review; Apple's guideline text and both stores' form fields were **not re-read** and are written from general knowledge. Re-check each store's current text before submitting, because they change.

## 1. User-generated content (Apple guideline 1.2, Google Play UGC policy)

Both stores expect an app with chat and public profiles to offer: filtering of objectionable content, a way to report it with a timely response, a way to block abusive users, and published contact details.

| Expectation                             | What exists                                                                                                                                                                            | Gap                                                                                                                                                                |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Filter objectionable content            | Server-side text filter on usernames, bios and chat (Phase 1)                                                                                                                          | Word list quality in Nigerian English, Pidgin, Yoruba, Igbo, Hausa is **unreviewed**. No image or audio content exists to filter (voice is live and not recorded). |
| Report content and users                | Report user or message from profile, chat and the voice panel; reason list; evidence snapshot (reported message plus five before it); 20 reports per day cap                           | Matches and voice sessions are reportable only as "the user"; there is no recording to review for voice reports (by design: spec §5).                              |
| Act on reports                          | Admin report queue, suspend, ban and reinstate with reasons; reports can be dismissed, audit log, bans cut REST and sockets at once (tests)                                            | **No stated response time and no staffed process.** Someone must own the queue before launch (who, hours, target such as 24 h).                                    |
| Block                                   | Block hides both users from each other everywhere, ends chats, prevents invites, quick matches and rooms (tests)                                                                       | none found                                                                                                                                                         |
| Contact details                         | Settings and sign-up show Privacy policy / Terms / Contact support **only when** `EXPO_PUBLIC_PRIVACY_URL`, `EXPO_PUBLIC_TERMS_URL`, `EXPO_PUBLIC_SUPPORT_EMAIL` are set at build time | The URLs and mailbox **do not exist yet**. A store build without them would show nothing.                                                                          |
| Terms that forbid objectionable content | Draft terms §2 and §4                                                                                                                                                                  | Lawyer review pending; Apple wants the terms to state there is no tolerance for objectionable content or abusive users.                                            |

## 3. Age rating and audience

- Product decision: **16+**, enforced by date of birth at sign-up (under-16 refused, tested).
- Apple: complete the age-rating questionnaire truthfully. Features that raise the rating: unrestricted user-to-user chat, user-generated profiles and voice. Expect the result to be a high teen tier, not 4+ or 9+. **The resulting rating is unverified**; it is computed by Apple from the answers.
- Google Play: complete the IARC questionnaire (users can interact, user-generated content shared, voice). Set the target audience to 16+ / adults only. **Do not opt in to the Families / "designed for children" programme.**
- No gambling, no real-money play, no paid entry, no ads in the MVP. State "no" for each.

Not collected: location, contacts, photos, health, financial information, browsing history, advertising ID. No third-party advertising or analytics SDKs are in the app (Sentry is the only optional one).

## 6. Sign-in

- Apple 4.8: because Google sign-in is offered, Sign in with Apple (or an equivalent privacy-preserving option) must be offered. It is implemented on the server; **no real Apple credentials have been used**, so it is unverified (Apple Developer account needed).
- Google sign-in: unverified without OAuth client ids.

## 7. App Review readiness

- Reviewers need a working demo account and a way to see a match: provide two ready accounts and note that Ludo and voice need a second device. Ludo ships **disabled** in the games table until the owner enables it.
- A reachable backend is required during review; the preview build points at the Render service (`eas.json`). Production URL not set.
- Store listing needs: privacy policy URL, support URL, marketing URL (optional), screenshots, description that does not claim availability in untested regions.

## 8. Things only the owner can do
