# Decisions

Defaults chosen without owner input are marked **(default)**. Owner decisions are marked **(owner)**.

| #   | Decision                                                                                                                                                                                           | Why                                                                            |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 1   | Minimum age 16, DOB collected at signup, age gate enforced server-side **(owner)**                                                                                                                 | Product decision                                                               |
| 2   | Voice via Agora; off by default per match **(owner)**                                                                                                                                              | Product decision                                                               |
| 3   | Tic-tac-toe is the first game (Phase 2), Ludo second (Phase 4) **(owner)**                                                                                                                         | Smaller rule set proves the session framework first                            |
| 4   | Own NestJS auth (JWT + rotating refresh) plus Apple/Google sign-in. Shared internal packages may be copied after review; separate DB, repo, credentials **(owner)**                                | Isolation from RRYDA                                                           |
| 5   | Access token: HS256 JWT, 15 min, `iss=gameverse-api`, `aud=gameverse-app`. Role and status are read from the DB on every request, not from the token **(default)**                                 | Bans and demotions apply on the next request                                   |
| 6   | Refresh tokens are opaque random values; only a sha256 is stored. Rotation with a token family; a 10 s reuse leeway covers client retry races; later replay revokes the whole family **(default)** | Detects theft without logging out users on flaky networks                      |
| 7   | Passwords hashed with argon2id (m=19456, t=2, p=1, OWASP minimum). Unknown-email logins spend equal hashing time **(default)**                                                                     | Resist offline cracking and account enumeration                                |
| 8   | Social sign-in never auto-links to an existing password account unless the provider email is verified; pre-hijacking guarded **(default)**                                                         | Prevents account takeover through unverified provider emails                   |
| 9   | Rate limits are in-memory (single API instance). A shared store is required before running more than one instance **(default)**                                                                    | Matches the "no multi-instance scaling" MVP scope; Redis only on measured need |
| 10  | Email: `console` (dev) and `memory` (tests) providers only. Config refuses both in staging/production until a real provider is chosen **(default)**                                                | Avoids silently dropping verification and reset emails in production           |
| 11  | Prisma 7 with `prisma-client` generator and `@prisma/adapter-pg`. Migrations are SQL files in `apps/api/prisma/migrations` **(default)**                                                           | Current Prisma major                                                           |
| 12  | Terms version is the placeholder `draft-1` until legal text exists **(default)**                                                                                                                   | Real terms and privacy policy are an owner/legal task before launch            |
| 13  | Error envelope `{ error: { code, message, details? }, requestId }` for every error **(default)**                                                                                                   | Stable client contract                                                         |

## Phase 1

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Why                                                                                                                                                                                                                                                      |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 14  | Profile is created at onboarding (`PUT /v1/me/profile`), not at registration. Username 3-20 chars `[A-Za-z][A-Za-z0-9_]`, unique case-insensitively **(default)**                                                                                                                                                                                                                                                                                                          | Registration stays small; uniqueness enforced by a DB unique index, races return 409                                                                                                                                                                     |
| 15  | Username changes are limited to once per 7 days; case-only edits are free **(default)**                                                                                                                                                                                                                                                                                                                                                                                    | Slows evasion of blocks/reports by renaming                                                                                                                                                                                                              |
| 16  | Settings default to friends-only for profile, online status and DMs; an absent row means defaults **(owner spec section 6)**                                                                                                                                                                                                                                                                                                                                               | Conservative privacy defaults                                                                                                                                                                                                                            |
| 17  | Text filter is a normalising blocklist (leetspeak, separators, accents) with strict and whole-word terms plus an innocent-word allowlist **(default)**                                                                                                                                                                                                                                                                                                                     | Cheap server-side first line of defence. The list is a **starter** and must be curated by moderators per market, including Nigerian Pidgin, Yoruba, Igbo and Hausa. Known limit: determined users will evade it; reports and moderators are the backstop |
| 18  | Reserved names (admin, support, bot, etc.) are rejected so users cannot impersonate staff or labelled bots **(default)**                                                                                                                                                                                                                                                                                                                                                   | Honesty rule 7: bots must be recognisable                                                                                                                                                                                                                |
| 19  | Friend requests: one row per user pair (sorted-pair unique key). Mutual requests (A->B and B->A) become a friendship. Rejection is silent: the sender is told "sent" and cannot resend for 30 days. Caps: 500 friends, 100 pending outgoing requests **(default)**                                                                                                                                                                                                         | Race-safe by construction; blocks harassment loops; bounds abuse                                                                                                                                                                                         |
| 20  | Block hides both users from each other (search, profile, requests answer 404, identical to "no such user") and ends any friendship or request in the same transaction **(default)**                                                                                                                                                                                                                                                                                        | Cannot probe whether someone blocked you                                                                                                                                                                                                                 |
| 21  | Social-graph writes run SERIALIZABLE with retry (accept vs block vs remove) **(default)**                                                                                                                                                                                                                                                                                                                                                                                  | READ COMMITTED allowed a friendship and a block to coexist in a race (verified by mutation test)                                                                                                                                                         |
| 22  | Friend-request sending is limited by the pending cap and the per-IP limiter, not a per-user rate limiter, because the throttler runs before authentication **(default)**                                                                                                                                                                                                                                                                                                   | A per-user limiter needs a post-auth guard; revisit if abuse appears                                                                                                                                                                                     |
| 23  | Accepting an already-handled request returns 404, not success **(default)**                                                                                                                                                                                                                                                                                                                                                                                                | Simple and unambiguous; the app should treat a 404 on accept as "already handled" and refresh                                                                                                                                                            |
| 24  | Chat is 1:1 only, one conversation per user pair. Sending is REST only (validated, idempotent on `clientMessageId`, rate limited 20 per 10 s per sender); the WebSocket is delivery only **(default)**                                                                                                                                                                                                                                                                     | One well-tested write path; the socket cannot be abused to bypass limits                                                                                                                                                                                 |
| 25  | WebSocket at `/ws`. The access token is the first frame (never in the URL). Sockets close at token expiry (4401) and the client reconnects with a refreshed token. Max 5 sockets per user, 4 KB frames, 30 frames per 10 s. In-memory hub, single instance **(default)**                                                                                                                                                                                                   | Tokens stay out of logs; bounded abuse. Multi-instance needs a shared pub/sub first (out of MVP scope)                                                                                                                                                   |
| 26  | A refusal to message (blocked either way, recipient's DM setting, inactive account) returns one generic `CANNOT_MESSAGE` 403. Conversations with a blocked user are hidden (404) both ways and reappear after an unblock **(default)**                                                                                                                                                                                                                                     | Does not reveal why                                                                                                                                                                                                                                      |
| 27  | Sending a message marks everything up to it as read by the sender (replying implies reading). Read position only moves forward. Message ids are UUIDv7, so id order is time order; two messages created in the same millisecond may order arbitrarily **(default)**                                                                                                                                                                                                        | Matches common chat behaviour; documented edge case                                                                                                                                                                                                      |
| 28  | Muting suppresses push notifications only (built in 1E); in-app delivery continues **(default)**                                                                                                                                                                                                                                                                                                                                                                           | Mute means "stop buzzing me"                                                                                                                                                                                                                             |
| 29  | Reports: user or chat message, 8 reasons, one open report per (reporter, reported, message) enforced by a unique key, 20 reports per reporter per day. A message report snapshots the message and the 5 messages before it, because moderator review of reported chat text is the only evidence we keep (no voice or message archive beyond the chat itself) **(default)**                                                                                                 | Evidence survives later deletion; abuse of the report button is bounded                                                                                                                                                                                  |
| 30  | Moderation actions are BAN, SUSPEND and REINSTATE, all indefinite until reversed (no timed suspensions in the MVP). Ban/suspend revoke all refresh tokens and close live sockets in the same moment; the HTTP guard rechecks status on every request **(default)**                                                                                                                                                                                                         | Simple to reason about; immediate effect required by the phase definition of done                                                                                                                                                                        |
| 31  | Role hierarchy: admins act on moderators and users, moderators only on users, nobody on admins or on themselves. Roles are read from the database on every request. Admin accounts can only be created directly in the database (seed or SQL), never through the API **(default)**                                                                                                                                                                                         | No privilege-escalation path through the API                                                                                                                                                                                                             |
| 32  | Staff lookups that expose email addresses are audited (the search text is not stored). The audit log is append-only (database trigger) and admin-readable only. Audit entries commit in the same transaction as the action **(default)**                                                                                                                                                                                                                                   | Accountability for staff access to personal data                                                                                                                                                                                                         |
| 33  | Staff account ids in reports, actions and the audit log are plain columns without foreign keys, so history survives staff changes **(default)**                                                                                                                                                                                                                                                                                                                            | History must not cascade away                                                                                                                                                                                                                            |
| 34  | Push notifications go through a `PushProvider` (none / expo / memory). The Expo sender is **unverified** against live Expo until a real device and project exist; `memory` is refused in staging and production **(default)**                                                                                                                                                                                                                                              | Honest labelling; tests use the in-memory provider                                                                                                                                                                                                       |
| 35  | Push text never contains message bodies: title is the sender's username, body is "Sent you a message". Push is skipped when the recipient is connected over WebSocket or has muted the chat **(default)**                                                                                                                                                                                                                                                                  | Lock-screen privacy; no double buzzing                                                                                                                                                                                                                   |
| 36  | No in-app notification table in the MVP; friend requests and chats are the inbox. Push is best effort and never fails the action that caused it; tokens Expo reports as gone are deleted; max 10 devices per user, and a token moves to whichever account registered it last **(default)**                                                                                                                                                                                 | Less to build and secure; shared phones behave correctly                                                                                                                                                                                                 |
| 37  | Presence is in-memory per instance, with a 5 s offline grace so reconnects do not flap. Visible to friends by default; `NOBODY` hides it; blocked, hidden, inactive and unknown users all answer `online: null` **(default)**                                                                                                                                                                                                                                              | No presence side channel                                                                                                                                                                                                                                 |
| 38  | Account deletion is two steps: signed-in user requests, a 1 h link is emailed to the registered address, and confirming needs both the session and the link. Personal data is erased and an anonymous tombstone row stays (status DELETED, DOB scrubbed). Reports, moderation actions and the audit log are kept on purpose and must be stated in the privacy policy. Banned and suspended accounts cannot delete themselves, so deleting cannot evade a ban **(default)** | App-store requirement; stolen session alone cannot erase an account                                                                                                                                                                                      |
| 39  | The admin app is plain React plus a small typed fetch client, not Refine's data-provider layer: it has four screens and Refine would add indirection without saving code. The unused `@refinedev/core` dependency was removed **(default)**                                                                                                                                                                                                                                | Less to maintain; can be revisited if the admin grows                                                                                                                                                                                                    |
| 40  | Admin session: access token in memory only, refresh token in `sessionStorage` (gone when the tab closes). Signing in with a non-staff account discards the session immediately. The audit tab is shown to admins only, and the API enforces the same rule **(default)**                                                                                                                                                                                                    | Staff tool never holds a player's session; UI hiding is convenience, the server is the control                                                                                                                                                           |
| 41  | Mobile session: refresh token in the OS keychain (`expo-secure-store`), access token in memory. A WebSocket close with code 4403 (banned, suspended, deleted) signs the app out locally **(default)**                                                                                                                                                                                                                                                                      | Standard token hygiene; bans take effect on the phone at once                                                                                                                                                                                            |
| 42  | Mobile chat treats the server as the source of truth: optimistic bubbles carry a stable `clientMessageId`, so a retry can never duplicate; after a socket reconnect the newest page is refetched to fill any gap **(default)**                                                                                                                                                                                                                                             | Unreliable mobile networks without double-sends                                                                                                                                                                                                          |
| 43  | CI boots the compiled `dist/` under plain Node (`smoke:dist`). Vitest transpiles on the fly and hid a CommonJS import failure that would have crashed production **(default)**                                                                                                                                                                                                                                                                                             | Tests alone do not prove the build starts                                                                                                                                                                                                                |
| 44  | Emails link to https landing pages served by the API, which hand the one-time token to the app through the `gameverse://` scheme. Mail clients only make https links clickable. Universal / app links replace this once a domain is configured **(default)**                                                                                                                                                                                                               | Works today with no domain or app-store setup                                                                                                                                                                                                            |
| 45  | Resend is the first real email provider (plain HTTPS, one request shape); the `EmailProvider` interface stays small so it can be swapped. Staging/production require a real provider, an API key and a real sender address **(default)**                                                                                                                                                                                                                                   | Simple to integrate; unverified until a key exists                                                                                                                                                                                                       |
| 46  | Draft Terms and Privacy Policy live in `docs/legal/` as drafts for a lawyer. The app does not display them yet and `CURRENT_TERMS_VERSION` remains `draft-1` **(default)**                                                                                                                                                                                                                                                                                                 | Legal text needs professional review before launch                                                                                                                                                                                                       |
