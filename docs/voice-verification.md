# Voice verification (Phase 3) — NOT RUN ON DEVICES

Status: **code complete, nothing verified on a real device or against real Agora.** Every row below is "not run" until the owner fills it in with a real result. Do not mark voice as working before then.

## What is verified by automated tests (fake provider, real Postgres and HTTP)

- The token endpoint accepts only seated players of an open match with another human and no block between them; strangers get the same 404 as a missing match; bots, finished matches and blocked pairs get 409 `VOICE_UNAVAILABLE`; token requests are limited per account (429); missing Agora credentials give 503.
- A real Agora v007 token is produced from test credentials and never contains or returns the certificate. **That Agora accepts this token is not tested.**
- Uids are seat + 1; the channel is `match_<id>`; tokens last 10 minutes and say when to renew.
- Usage sessions: one open session per player and match, join and leave are idempotent, seconds are recorded, a sweeper closes sessions when the match ends (counted to the moment it ended) or after 3 hours, and rows survive account deletion without the user id.
- The phone-side flow (permission, token, join, renewal, reconnect, mute, leave, speaker indicators) runs against a fake engine in `packages/shared-types` tests.

## How to run the check

1. Set `AGORA_APP_ID` and `AGORA_APP_CERTIFICATE` for the API (never commit them). Leave `VOICE_PROVIDER` unset (`agora`).
2. Build a development client on both phones (`eas build --profile development --platform android`).
3. Sign in on both, start a private room (code) and join, then tap **Join voice** on both.

## Known limits

- Blocking during a call ends the blocker's voice at once, but the blocked player's call keeps running until their next token renewal (up to about 9 minutes) is refused; there is no server-side kick yet.
- The first-run flow on iOS: the microphone prompt appears when the engine opens the microphone, so a refusal arrives as an engine error rather than the friendly "denied" screen.
- The Android foreground service uses `@notifee/react-native`; its manifest entry is generated by `plugins/with-voice-foreground-service.js` (checked with `expo prebuild`, not run on a phone).
- The Phase 0 spike was never run, so "Agora works in this stack at all" is itself unproven. If it fails, the fallback decision is the owner's (see `docs/voice-spike.md`).
